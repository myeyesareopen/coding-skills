# 路由与验收

主代理在派发前给出简短路由理由。难度依据是未决判断、模块耦合和失败影响，不是文件数量。DeepSeek 保留原执行技能的受限实施职责；扩大权限或开放设计能力不能靠更长提示词补偿。

## 判断顺序

1. 很快可完成的局部低风险修改或快速只读核对，留给主代理，除非用户明确要求委派。
2. 方案、契约、范围、依赖和验收都已确定，可由 DeepSeek 实施局部代码、修复、重构或定向核对。不把它作为开放研究、需求分析或架构代理。
3. 仍需跨模块调查/推理、复杂算法、并发/事务设计或安全判断，使用 Codex gpt-5.6-sol。复杂实现和独立风险验收使用 high；常规探索使用 medium。
4. 关键需求、架构取舍、跨任务契约和集成由主代理确定；可让 Codex 提供证据和建议。存在未决契约时先解决依赖，不能让多个执行者各自解释。

| 任务 | 处理方式与原因 |
|---|---|
| 单文件修改错误提示 | 主代理直接处理，交接开销大于收益 |
| 按已固定格式新增 DTO、局部校验和路由适配 | DeepSeek，接口与可观察结果已确定 |
| 按明确真值表修复边界判断并补定向回归 | DeepSeek，规则无需执行者另行设计 |
| 调查多个模块间未知的状态覆盖根因 | Codex，不能把未知根因当成受限修复 |
| 实现跨请求幂等、短事务、状态回写与过期保护 | Codex high，一致性边界和失败交互复杂；SQL/事务核心保持同一所有者 |
| 高风险迁移、认证边界或状态机的独立验收 | Codex high 或主代理，不能仅采信实现者自验 |

复杂功能内仍可以提取契约已冻结的低风险适配任务交给 DeepSeek，但不要按函数机械拆碎，或让低风险任务反向决定关键契约。

## 任务单

- 目标及可观察行为，派发时基线（SHA/已有diff/必要前置补丁）。
- 独占可写范围、只读上下文、禁止修改区域和共享资源。
- 实施方案、相关调用链、字段/错误/返回契约。
- 依赖是否已就绪；实施者不允许自行扩大的边界。
- 验收场景与实际检查命令；必需检查与主代理后续联调分别标明。
- 验收证据和剩余限制的报告方式。

运行时模型、凭据、参数、环境迁移和权限决定不能写成实施者自行选择的开放项。DeepSeek 使用现有 JSON 格式，把上述内容写入 projectContext、instructions、acceptance、checks，不添加 runner 不消费的自定义协议字段来假装生效。

## 状态及异步任务的验收

仅对涉及相应风险的任务使用下表。主代理填写业务决定，写明“触发条件 → 预期结果 → 验证方式”；不能只要求“完善测试”。低风险小修改无需完整清单。

| 风险 | 派发前需要确定 |
|---|---|
| 重复提交 | 同键同输入如何重放；同键异输入如何拒绝；不同键是否允许同一业务对象并发 |
| 异步结果 | 输入或阶段改变后旧结果如何处理；完成期限；迟到完成和状态查询的先后顺序 |
| 数据一致性 | 哪些写入必须同一事务；如何避免部分结果；跨对象归属约束 |
| 错误和恢复 | 明确失败与结果未知如何区分；允许重试的触发条件和费用边界 |
| 协议差异 | 服务端、客户端、模型输出 schema 和数据库的类型/枚举/范围/编号是否一致 |

测试应验证实际行为，例如“第二次请求未调用上游”“旧任务未改变新版项目”，而不是只检查状态常量存在。必需检查未通过不能作为已验收交付；主代理仍检查实际 diff 和组合行为。
