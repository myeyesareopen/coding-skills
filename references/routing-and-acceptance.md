# 路由与验收

主代理在派发前给出简短路由理由。难度依据是未决判断、模块耦合和失败影响，不是文件数量。DeepSeek 保留原执行技能的受限实施职责；扩大权限或开放设计能力不能靠更长提示词补偿。

## 判断顺序

1. 一处无需调查/设计的明显修正或快速只读核对可由主代理直接完成。完整功能、连续多处修复和带回归验证的行为改动不能只凭“改动小”套用例外。
2. 方案、契约、范围、依赖和验收都已确定，必须由 DeepSeek harness 实施代码、修复、重构及必要定向测试。只有一个任务也走单任务批次；不能以并行收益不足为由改用 native worker。
3. 尚缺事实或需要常规推理时，使用 gpt-5.6-sol medium 做只读调查/方案辅助，较难可用 high。完成后由主代理固定方案，将实施重新路由给 DeepSeek；不要预先给调查者代码写权限。
4. 对无法局部化的因果链、困难算法或多个一致性/安全边界互相制约的未决设计，使用 gpt-6-astra high，任务单写明具体复杂性。复杂核心中推理与代码修改确实不可分离时才允许 Codex 实施；其余已冻结的外围实现回到 DeepSeek。sol 明确暴露能力缺口也可据此升级，不因一次工具/测试故障升级。
5. 独立评审默认 sol medium/high；只有评审本身需要上述复杂推理才使用 astra。关键需求、架构取舍、跨任务契约和集成由主代理确定；存在未决契约时先解决依赖，不能让多个执行者各自解释。
6. harness 例外需实际检查证据：任务单格式错误先修正，槽位忙先等待；确定安装/凭据/运行故障本轮无法恢复时，可说明原因并用 sol 接续受限实现。保留旧产出、确认旧执行者停止后才转交写权限；不能把没有尝试过当作不可用。

| 任务 | 处理方式与原因 |
|---|---|
| 单文件修改错误提示 | 主代理直接处理，交接开销大于收益 |
| 按已固定格式新增 DTO、局部校验和路由适配 | DeepSeek，接口与可观察结果已确定 |
| 按明确真值表修复边界判断并补定向回归 | DeepSeek，规则无需执行者另行设计 |
| 调查多个模块间未知的状态覆盖根因 | sol medium/high 只读调查；固定修复方案后交 DeepSeek |
| 已明确规则和检查的多文件接口适配 | DeepSeek；文件多或含路由/SQL不构成 Codex 写任务理由 |
| 设计跨请求幂等、事务回写与过期保护，多个一致性策略仍互相制约 | astra high 处理复杂设计/不可分离核心；SQL/事务核心保持同一所有者，固定外围适配交 DeepSeek |
| 按已定规则增加幂等键格式校验和错误映射 | DeepSeek；不能仅见“幂等”就升级模型 |
| 按清晰检查项验收迁移或认证边界 | sol high；复杂攻击链/状态交错证明才考虑 astra |
| sol 找到明确缺陷并给出可执行修复方案 | 主代理确认后派 DeepSeek，不能顺手让 explorer 改代码 |
| harness 报可写范围冲突或无空闲槽位 | 修正分批/排队；不视为改用 Codex 的理由 |

复杂功能内仍可以提取契约已冻结的低风险适配任务交给 DeepSeek，但不要按函数机械拆碎，或让低风险任务反向决定关键契约。

## 任务单

- 目标及可观察行为，派发时基线（SHA/已有diff/必要前置补丁）。
- 独占可写范围、只读上下文、禁止修改区域和共享资源。
- 实施方案、相关调用链、字段/错误/返回契约。
- 依赖是否已就绪；实施者不允许自行扩大的边界。
- 验收场景与实际检查命令；必需检查与主代理后续联调分别标明。
- 验收证据和剩余限制的报告方式。

运行时模型、凭据、参数、环境迁移和权限决定不能写成实施者自行选择的开放项。DeepSeek 使用现有 JSON 格式，把上述内容写入 projectContext、instructions、acceptance、checks，不添加 runner 不消费的自定义协议字段来假装生效。

## 状态及异步任务的验收

仅对涉及相应风险的任务使用下表。主代理填写业务决定，写明“触发条件 → 预期结果 → 验证方式”；不能只要求“完善测试”。低风险小修改无需完整清单。

| 风险 | 派发前需要确定 |
|---|---|
| 重复提交 | 同键同输入如何重放；同键异输入如何拒绝；不同键是否允许同一业务对象并发 |
| 异步结果 | 输入或阶段改变后旧结果如何处理；完成期限；迟到完成和状态查询的先后顺序 |
| 数据一致性 | 哪些写入必须同一事务；如何避免部分结果；跨对象归属约束 |
| 错误和恢复 | 明确失败与结果未知如何区分；允许重试的触发条件和费用边界 |
| 协议差异 | 服务端、客户端、模型输出 schema 和数据库的类型/枚举/范围/编号是否一致 |

测试应验证实际行为，例如“第二次请求未调用上游”“旧任务未改变新版项目”，而不是只检查状态常量存在。必需检查未通过不能作为已验收交付；主代理仍检查实际 diff 和组合行为。
