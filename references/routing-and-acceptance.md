# 路由与验收

先选择最少交接即可完成验收的路径，再决定模型。委派应产生独立进展、补足能力或降低实质风险，不为遵守形式创建代理。

## 路由例子

| 任务 | 路由与检查 |
|---|---|
| 两三个关联文件中的明确校验修复，低影响且有定向测试 | 主代理直接修改，运行相关测试一次；不因多文件强制委派 |
| 一个模块内增加普通接口或修复常规 bug | 一个 Luna max 所有者完成定位、修改、自测，主代理看 diff 与证据 |
| 未知根因需要较多调查，但修复范围可预先限定 | 一个 Sol medium/high 任务包含调查和范围内修复权限；无需再转 Luna |
| 只要求定位根因或修复需要改变公共契约 | Sol 只读调查；主代理决策后可明确授权原代理实施，不自动获得写权限 |
| 多个互不依赖的服务 | 每服务一个所有者并行；公共契约先确定，集成检查由主代理统一一次 |
| 多个一致性策略互相制约、难算法或协议证明 | Astra high 负责复杂核心，必要时一次独立评审 |
| 认证/迁移/并发等高影响改动，方案清楚 | 按实际能力与风险分配实施，安排针对边界的必要验证；不只凭关键词升级或降级 |
| 已通过全部必要检查，无后续改动或新疑点 | 交付，不新起 verifier，不重复跑同一套测试 |
| 用户未明确要求 DeepSeek | 不执行 legacy doctor/bootstrap/run/aux；缺少 dsh/key 不阻断 native 工作 |

用户指定的模型、强度和独立评审要求优先。当前 Luna max 默认保持不变；如将来启用动态强度，必须依据 [路由器评估](router-evaluation.md) 的对照结果与明确偏好，而不是看到分类概率就自动降低。

## 验收证据与检查所有权

派发前写清触发条件、预期结果及必要检查。检查报告包含命令、结果、代码状态（commit 或相关文件/补丁标识）和实质环境差异。简单共用工作区可用主代理已记录的基线及后续 diff，无需每次创建专门提交。

主代理检查真实 diff、范围和证据。若所有者已在同一代码状态通过定向测试，则复用结果；如果合并多个模块、修改依赖或返工，运行受影响的检查。禁止用“子代理说完成”代替验收，也不要用机械复跑代替判断。

涉及相应风险时才检查以下边界：

- 幂等：重复请求、同键异内容、并发重放。
- 异步：迟到回写、取消、版本变化和超时。
- 事务：中途失败、部分完成与跨对象归属。
- 安全：授权边界、敏感数据暴露与错误处理。
- 接口：生产者/消费者的字段、枚举、版本与错误语义。

失败后由原所有者优先修复具体缺陷，不自动重读整个项目或重启完整流程。必需检查未通过、关键条件未验证或有阻断时不能交付完成。
