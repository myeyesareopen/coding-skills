# Codex 角色任务单

仅用于 native Codex subagent；DeepSeek 使用 [专属调用协议](deepseek-dispatch.md)，不要将 native 模型参数或此报告格式传给 dsh。

创建前按 SKILL.md 完成路由判断，确认所选模型及强度在当前工具可用，预留辅助名额并检查平台上限。默认显式 model="gpt-5.6-sol"、reasoning_effort="medium"、fork_turns="none"；较难用 sol high。仅具体复杂性或已有能力缺口支持升级时用 model="gpt-6-astra"、reasoning_effort="high"、fork_turns="none"。不能省略 model 而继承 astra。主代理填写最小充分上下文，不传整段对话，不要求代理自行加载未知项目知识。所有角色禁止再次创建子代理或调用 dsh；需要 DeepSeek 实施时向主代理交回方案，由主代理实际派发。

## 实施 worker

这是例外通道：仅用于推理与修改不可分离的复杂核心，或已有错误证据证明 harness 本轮无法恢复的接续实现。方案、范围和验收已明确的普通实现不得使用本模板绕过 DeepSeek。调查结束不会自动获得实施授权。

```text
角色：Codex 实施者
模型/强度：gpt-5.6-sol medium/high；满足复杂性门槛才用 gpt-6-astra high
路由例外：无法拆开的未决判断，或 harness 阻断的实际命令/错误证据；如使用 astra，说明 sol 不适合的原因
目标：具体行为变化
工作目录/基线：绝对路径、基线SHA或已检查的未提交状态
可写范围：独占文件或模块
只读上下文：相关指令、类型、调用链和测试
禁止修改：其他执行者范围、共享契约或明确排除内容
已确定的方案/契约：输入、输出、错误、边界、必须保持的行为
依赖：已进入工作区的前置结果，以及不能自行决定的事项
验收：触发条件、预期结果、必需检查命令
工作规则：先检查已有改动，只写所属范围；不启动遗留后台服务，不联网部署、不push；不创建子代理。默认不commit，除非此任务明确授权。
交付：STATUS（COMPLETE/PARTIAL/BLOCKED）、SUMMARY、FILES、逐项验收证据、实际检查与未运行原因、COMMIT（没有则N/A）、RISKS。
```

使用 high 不自动意味着使用 astra。复杂核心不会因为被命名为“常规接口”而降低路由；边界明确的多模块常规实现应交给 DeepSeek，仅在上述 harness 故障例外下使用 sol medium。

## Explorer

默认 sol medium；较难根因调查用 sol high；满足复杂性门槛才使用 astra high。任务单列出需要回答的问题、只读范围及期望证据。报告文件/符号、调用流程、最小改动位置、依赖与未知项，明确事实和推断，并给出后续 DeepSeek 可用的实施步骤和验收建议。保持源码、Git 状态和外部系统只读，不把猜测当成已决定的实现方案，不自行转为实施者。

## Verifier

默认 sol；涉及迁移、安全、并发/事务时使用 high，常规独立核对使用 medium。仅验收本身涉及复杂证明或多边界推理时使用 astra high。给出基线/待审产物、只读范围、验收条件和可执行检查。验证题意/契约、影响调用方、失败与顺序场景、相关测试，并区分阻断问题与非阻断建议。

默认不修代码；测试如需生成缓存，使用指定隔离输出目录，不能把“只读审查”解释为允许改源文件。需要修复时由主代理重新分配明确可写范围。报告 PASS/FAIL、逐项证据、检查结果/未运行原因、阻断问题、非阻断问题和置信限制。

独立验收者不能只复述实施者的自测结论；应检查实际产物。无需给每个小任务固定增加 verifier。
