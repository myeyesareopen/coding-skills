# Codex 角色任务单

仅用于 native Codex subagent；DeepSeek 使用 [专属调用协议](deepseek-dispatch.md)，不要将 native 模型参数或此报告格式传给 dsh。

创建前确认 gpt-5.6-sol 在当前工具可选模型中，预留辅助名额并检查平台上限。使用 fork_turns="none"。主代理填写最小充分上下文，不传整段对话，不要求代理自行加载未知项目知识。所有角色禁止再次创建子代理或调用 dsh。

## 实施 worker

```text
角色：Codex 实施者
目标：具体行为变化
工作目录/基线：绝对路径、基线SHA或已检查的未提交状态
可写范围：独占文件或模块
只读上下文：相关指令、类型、调用链和测试
禁止修改：其他执行者范围、共享契约或明确排除内容
已确定的方案/契约：输入、输出、错误、边界、必须保持的行为
依赖：已进入工作区的前置结果，以及不能自行决定的事项
验收：触发条件、预期结果、必需检查命令
工作规则：先检查已有改动，只写所属范围；不启动遗留后台服务，不联网部署、不push；不创建子代理。默认不commit，除非此任务明确授权。
交付：STATUS（COMPLETE/PARTIAL/BLOCKED）、SUMMARY、FILES、逐项验收证据、实际检查与未运行原因、COMMIT（没有则N/A）、RISKS。
```

较复杂实现使用 high；边界较明确但跨多个关联模块的常规实现可用 medium。复杂工作不会因为被命名为“常规接口”而降低强度或路由给 DeepSeek。

## Explorer

使用 medium；大范围复杂根因调查可用 high。任务单列出需要回答的问题、只读范围及期望证据。报告文件/符号、调用流程、最小改动位置、依赖与未知项，明确事实和推断。保持源码、Git 状态和外部系统只读，不把猜测当成已决定的实现方案。

## Verifier

涉及迁移、安全、并发/事务时使用 high；常规独立核对使用 medium。给出基线/待审产物、只读范围、验收条件和可执行检查。验证题意/契约、影响调用方、失败与顺序场景、相关测试，并区分阻断问题与非阻断建议。

默认不修代码；测试如需生成缓存，使用指定隔离输出目录，不能把“只读审查”解释为允许改源文件。需要修复时由主代理重新分配明确可写范围。报告 PASS/FAIL、逐项证据、检查结果/未运行原因、阻断问题、非阻断问题和置信限制。

独立验收者不能只复述实施者的自测结论；应检查实际产物。无需给每个小任务固定增加 verifier。
