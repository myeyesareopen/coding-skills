# 工作区、集成和恢复

以下规则同时适用于 native Luna/Codex 执行者，以及用户明确要求后启动的 legacy DeepSeek 执行者。runner 的冲突检查覆盖其管理的 legacy DeepSeek 任务；native 代理的范围由主代理纳入同一所有权清单。纯 native 使用平台容量管理，只有混合 DeepSeek 执行时才用 aux；aux 预留不能代替文件和资源检查。

路径声明是调度约束，不是操作系统级写入沙箱；主代理仍须检查实际 diff 是否越界，不能将通过 validate 视为文件访问已被强制隔离。

## 共用 checkout

用于读写范围完全分离的小型任务。派发前记录 git status、已有 diff/未跟踪文件；不要 reset、stash 或覆盖用户改动。主代理与其他工具也不能在执行者拥有的范围内同时写入。同批只读路径不能覆盖另一任务的可写路径：例如双方都“读整个项目”而分别改两个模块，声明上仍有冲突，应缩小读取范围或分批。

记录派发时的补丁或相关文件哈希，以区分用户已有修改和执行者修改。主代理补修前再保存执行者的交付补丁与检查证据，避免事后评估把返工当作原始交付。

依赖 lockfile、公共 types、schema、索引导出、生成文件的改动指定一个所有者先处理，验收后再开消费方任务。每个任务的构建/测试若会写公共缓存、占固定端口或改同一数据库，把资源登记为 exclusiveResources，或者配置隔离路径/端口。不要靠文件后缀推断这些资源独立。

## 隔离 worktree

用于较大、持续并行写入或需要独立提交的任务。先检查已有 dirty 状态，固定基线 SHA。主代理创建路径明确的 worktree 与分支，每个执行者拥有一个工作区；必要的未提交前置变化要明确传入基线，不能误以为新 worktree 会自动包含它们。不得为了做基线提交而混入用户的无关变更。

不同 worktree 中也要声明同一公共资源的稳定标识，例如 `project-X:public-contract`、`project-X:db-fixture`。源代码接口有依赖时仍分批；不要利用物理路径不同骗过冲突检查。

默认 worker 不提交、不 push。主代理验收 diff 后按需要自行提交/逐项整合；若明确授权 worker 本地提交，将授权和提交范围写入任务单，返回 commit SHA。集成依赖任务前确保前置结果已实际进入它的工作区，不能只看到前置任务 done 就启动。

## 恢复与清理

任务 JSON、runtime-home、result.json、summary.json 和日志放在独立运行目录，避开项目构建和测试会清理的路径。不要把共享运行目录分配给不同批次；需要重新派发时使用新目录，并在任务上下文中明确需要接续的旧结果。

普通任务的长日志可写入 `work/<task-id>/logs/`，现有项目约定优先；不得覆盖用户文件、混入可提交源码或把敏感信息留在日志。沿用 legacy runner 时，launcher 日志放在 batch.outputDir 的父目录或同级目录，outputDir 本身必须保持不存在直到 runner 创建。简单短命令不必落盘。长任务需要恢复时可维护一份 `work/<task-id>/status.md`，仅记录关键状态与证据位置，不复制原始日志。

清理只针对明确属于已结束任务的可再生成日志，并遵循用户或项目已设定的保留期；没有保留期时不自动删除。先核对任务结束、进程不再使用文件、验收完成、无待诊断失败，且恢复摘要/关键证据仍可用。保护未验收失败现场、用户交付物、补丁、凭据、锁与其他任务的数据；不能因为文件旧就删除。删除前核对规范化绝对路径位于本任务日志目录内，拒绝指向目录外的链接或重解析点；Windows 使用 PowerShell 的 LiteralPath 原生操作。按保留期清理属于磁盘管理，不宣称会减少已消耗的 token 或清空当前上下文。

不直接修改 Codex 活跃或历史会话数据库、rollout、聊天 tool-call 记录；本技能不自建定时删除任务或修改全局日志/上下文配置。只有用户明确要求安排定时清理时才创建自动化，并限定上述可清理范围。

超时、失败、结果丢失时先确认进程是否退出，再读工作区 status、diff、最近提交，保留有价值的结果。不要一边旧执行者还在写，一边启动替代者修改相同文件。legacy runner 在停止失败或不确定时保留槽位，不把未知进程当作已停止；native Luna 不因 DeepSeek 未运行而等待或切换。

用户明确要求 legacy DeepSeek 时，`dispatch.mjs slots` 列出槽位和 owner/child PID。进程异常退出可能留下槽位或 mutex；不要按年龄自动清除。确认 owner、dsh 子进程及它们派生的工具进程均已终止后，在已核对的状态目录内删除那个确定失效的槽位文件或 mutex 目录；不能批量清空其他任务的锁。无 DeepSeek 请求时 native Luna 路径不启动或清理 DeepSeek。Windows 操作全程用 PowerShell -LiteralPath，先确认绝对路径处于状态目录内。

集成及验证通过前保留 worktree；清理前核查路径、未提交修改与结果是否已保存，用 git worktree remove 正常移除，不常规使用 force。失败现场保留供接续任务使用。
