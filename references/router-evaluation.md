# 可选路由器：Jev 评估

评估日期：2026-09-22。本文是接入方案与试验条件，不是已经实现的功能。当前没有 Jev 客户端、API key 配置或自动路由调用，技能默认仍按主规则执行；仅请求评估不意味着授权上传项目数据或运行付费实验。

## 结论与依据

Jev 可以对任务类型、复杂性等返回结构化判断，再由本地规则选择模型/强度。是否改善本技能的端到端速度和 token 消耗尚未实测；现阶段优先减少交接与重复读取，Jev 保持可选。

- 官方当前提供 `jev-1.13.0`，按输入计费 $0.042/百万 token，输出免费；英文表现最佳，中文等输入需单独验证。固定版本比使用会漂移的 latest 更适合对照实验。[官方模型文档](https://docs.typesafe.ai/models)
- 路由的收益不能直接归因于 Jev：一个 5,835 条留出查询的作者实验中，加入 Jev 的方案可在与最佳单模型相同准确率下降低约 33% 估算成本，但移除 Jev 的历史证据路由表现几乎相同。它使用预计算答案，不是此技能的实时编码实验，也不是 Codex token 节省证明。[实验与消融](https://github.com/TokenTrim/jev-routing-experiment)
- 技术推断：本技能的主代理已经需要理解需求与文件范围。若只为了复述其已有判断再调用 Jev，会增加请求、输入 token 和维护成本；只有分类改变了不合适的模型/强度选择并减少返工时，才可能抵消开销。

分类输出不是代码可通过验收的概率。不能以“高置信度”替代权限、需求确认、代码检查或实际测试；也不能把较低模型单价等同于较少 token。

## 可选接入位置

若未来明确要求实现，放在 native `spawn_agent` 之前，由主代理管理：

1. 规则先处理用户明确指定的模型/强度、直接处理路径、只读/可写权限、风险与可用模型。简单明确任务直接走规则，不调用 Jev。
2. 仅对路由有实质不确定性的待派发任务发送精简摘要：目标、范围、未知项、依赖和失败影响。不给完整对话、密钥、无关源码或客户数据。
3. 一次请求判断工作类型、推理复杂性、失败影响、信息是否充分、是否需要拆分；本地策略把这些字段映射到允许的 model/reasoning_effort 组合，不让外部输出生成工具名、权限或自由文本命令。
4. 保留用户约束与风险下限。复杂性低不代表影响低，高影响任务不能仅凭分类降级；分类本身也不直接授予写权限。
5. 设置有界超时和失败回退；异常、低置信度、信息不足、版本不匹配或未验证语言使用原规则，不阻塞任务，不循环重试路由。不要自动换成最贵模型。
6. 同一任务摘要、规则版本、候选模型和 Jev 版本未变时复用决策，只有需求/风险变化或真实能力缺口才重评，不逐工具调用路由。只能选择后续执行者，不能靠技能切换当前主代理模型。

## 动态推理等级的试验

现有 Luna max 默认先保留。未来授权对照试验时，候选可以包含 Luna medium/high/max、Sol medium/high 与 Astra high；先检查平台实际支持，不假设等级与耗时线性对应。

分开测试“换模型”和“换推理等级”，避免无法解释收益来自哪里。复杂任务可以直接使用合适模型，不要求先让低档失败；同一已知能力缺口不重复付费碰运气。

先比较三组：优化后的规则基线、规则加 Jev 建议、无 Jev 的历史成功率策略。可先用脱敏样本验证分类，再在授权的真实任务中旁路记录；旁路不改变执行选择，只能评估一致性与分类开销，不能证明候选执行模型的反事实成功率。

效果评估需要隔离工作区内的配对任务或按任务类别随机分流，保证相同验收条件，并冻结规则、版本与分组，避免用评估集调阈值。起步可积累 100–300 个覆盖常见类型的样本；数量不是统计充分性的保证，按类型、风险、中文输入和误差区间报告。

记录端到端 P50/P95、首次验收通过率、重试/升级率、主代理与子代理用量、路由开销、总成本及返工。各供应商 token 分开报告，缺失则写未知；缓存输入与推理输出不重复计数。相同任务上的总比较须包含路由、失败尝试、重复上下文和集成成本，不能仅比较最终成功的模型调用。

启用条件由实际结果决定：质量达到事先约定的可接受下限，且目标指标改善；分别报告速度、token 与费用，不把一个指标的改善冒充全部改善。若无法证明相对简单规则的增益，就保留规则路由。更换 Jev 或候选模型版本后重新校验；出现误路由或延迟恶化时回退。
